# 21 · 业务闭环、跨轮记忆与恢复验证

## 请求与状态生命周期

本轮增加 `pending_actions` 关系表，保存 action_id、session_id、user_id、完整服务端提案、创建时间和 UTC 过期时间。初始化使用 metadata.create_all 创建新表，不改动原业务表。提案与当轮消息在同一事务提交；普通请求和 SSE 使用同一持久化路径。

确认请求只携 action_id。服务端先校验会话归属，再从数据库读取原提案，校验用户、会话和 15 分钟有效期，恢复原工具与参数；不信任客户端重新提供的参数。确认后强制 AGENT，直接执行已核对动作。设备状态、预约窗口与冲突仍在真正写入前重新校验。

成功写入与 action ID 幂等记录由请求事务一起提交。有效期内重复确认复用已有结果，避免顺序重试重复登记。提案保留至过期，未实现令牌单次消费、并发首次确认排他或自动清理历史提案；不承诺 exactly-once。多个副本须连接同一数据库，真实多副本并发仍未压测。

实现：`app/repositories/action_repository.py`、`app/repositories/models.py`、`app/services/chat_service.py`、`app/agents/nodes/executor.py`。

## 记忆如何影响下一轮

ChatService 加载最近 20 条消息及 SessionRow.summary。新增 resolve_context 节点位于护栏之后、意图之前，保留原始 user_query，另存 resolved_query。明确的单设备指代可本地补全；复杂追问和缺字段补充使用模型改写。多个设备的指代不明确时不猜编号，模型不能增加历史中不存在的设备 ID，也不能把普通追问改成写操作授权。

路由、检索和规划使用补全后的问题；生成提示同时提供原问、补全问题、最多 8 条近期消息和摘要。背景由 JSON 编码，近期内容每条最多 600 字符、摘要最多 1600 字符，总长度最多 6800 字符。历史仅帮助理解用户，不是实时设备事实、制度来源或写入授权。

每轮达到 12 条消息时更新运行摘要，并带入旧摘要，避免上下文超过最近消息窗口后丢失旧信息。高 token 阈值仍保留原有分级压缩，压缩节点在回答之后；当前不是完整提示的精确 token 预算，也不是长期知识记忆。摘要由模型生成，可能遗漏或失真。

实现：`app/memory/context.py`、`app/agents/nodes/router.py`、`app/agents/nodes/generate.py`、`app/memory/summarizer.py`、`app/agents/nodes/memory.py`。

## 业务流程的验证范围

- 预约：提出带时区的设备时段与用途 → 返回确认卡而不写入 → 确认 → requested 记录 → 数据库查询时段核对。另测重复确认和相同时段二次申请冲突。
- 报修：设备编号和具体故障 → 确认卡 → 确认后 open 工单 → 数据库核对数量。缺字段不能用“待用户提供”占位生成可执行提案。
- 重启：真实模型 E2E 重建 ChatService、状态图、数据库引擎及连接池，复用同一 SQLite 文件；本地集成测试另用两个独立 Python 进程先提案再确认。均不等同于主机掉电、多实例并发或生产灾备。
- 记忆：设备状态后追问“它在哪里”；先提供样品代号，经过多轮摘要并重建服务后回忆代号。确认写入和记忆不是依靠固定回复伪造，报告保存原始答案与数据库前后数量。
- MULTI：增加四条组合制度问题，保存实际 retrieval_rounds。进入 MULTI 并执行取证不代表一定执行两轮以上；充分性判定可以第一轮停止。

测试入口为 `tests/integration/test_conversation_workflows.py`。真实 E2E 使用 `eval/workflows.py` 的隔离文件数据库，不修改开发数据库。

## 扩充后的评测协议

保留原 24 条意图与 8 条 E2E，意图扩至 120 条；E2E 为 24 条单轮和 8 个多轮场景，共 32 场景 / 51 次请求。覆盖问候、闲聊、能力咨询、人工联系、安全、设备、预约、报修、越权；多轮覆盖确认、幂等、恢复、冲突、槽位补充与摘要。

问题在运行前固定并记录 SHA256，首轮失败全部保留，修改代码后对同一题集复测。因开发者根据失败修正提示与逻辑，这些结果属于开发回归，不能作为独立留出集成绩。报告记录每项检查的 passed/n、每轮回答、业务计数和失败条件；关键词全匹配只是字面指标。

本轮真实评测与结果见[当前实测](../eval/LABMATE_MEASURED.md)。付费 API 余额不足时必须先恢复账户，不把规则回退冒充真实模型；中断记录单独保留。
